# 宇航员猫娘帮助文档

使用 VitePress 构建的宇航员猫娘 Bot 使用说明，内容以 `bot/meowmeow` 当前实际启用的插件和命令注册为准。

## 本地开发

```bash
npm install
npm run dev
```

## 构建与预览

```bash
npm run build
npm run preview
```

VitePress 构建产物位于 `.vitepress/dist`。

### 词云可用性复核

2026-10-19 在 tclab 运行 bot 使用的 `.venv` 中只读检查：`nonebot-plugin-wordcloud 0.9.0` 已安装，但 `nonebot_plugin_chatrecorder` 模块及对应发行包缺失。依赖链为 `nonebot_plugin_wordcloud` → `require("nonebot_plugin_cesaa")` → `require("nonebot_plugin_chatrecorder")`，会在命令注册前加载失败。

初次核对仅确认了安装与命令源码，误将词云写进公开帮助；现已撤下首页、速查和工具页中的词云说明。本次没有安装依赖、改动 bot 配置或重启服务。今后应同时核对加载依赖和运行条件，不能把 `pyproject.toml` 中声明的插件直接视为可用功能。

## 后续功能建议（调研，尚未实现）

以下是结合现有能力提出的增量设计，不应作为可用指令写入用户帮助。成本为相对估计，不是排期承诺。

| 优先级 | 建议 | 与已有功能的区别 | 最小可用范围与主要依赖 | 相对成本 |
| --- | --- | --- | --- | --- |
| 高 | 成绩快照与进步对比 | 现有 PK 比较两个人；新增同一玩家两次查询的变化 | 用户主动保存快照，比较新入 B50、掉出 B50、单曲提升、净增 Rating；按查分器和游戏版本隔离，不把换版降定数当成退步 | 中 |
| 高 | 目标歌单与练习清单 | 已有推分建议和牌子进度；新增保存目标、排除不想练的歌、跟踪完成情况 | 先支持一个牌子或等级目标，生成一组可复用清单；每次更新仅显示剩余目标与新增完成，复用已有成绩和渲染 | 中 |
| 高 | 版本差异对照 | 已有单曲定数历史与历史表；新增两版曲库的汇总比较 | 新增/删除曲、定数升降、等级变化；先做静态曲库对照，再考虑套入个人成绩估算 Rating 变化 | 低至中 |
| 中 | 成绩更新摘要与最近游玩 | 最佳成绩列表不能等同于最近一局或完整游玩记录 | 落雪可对接最近记录与历史；水鱼先支持快照间“成绩更新摘要”，不伪造实际游玩时间；必须分别显示同步时间、游玩时间和数据来源 | 中 |
| 中 | 收藏品达成路线 | 已有收藏品来源与地图路线；新增结合个人成绩列出尚缺条件 | 先做能由公开条件与成绩计算的称号/姓名框，逐项列出缺哪首歌、哪张谱、什么目标；没有个人收藏状态的数据只显示条件完成情况 | 中至高 |
| 中 | 查询数据状态 | `ping` 主要看 Bot 响应；新增解释成绩为什么没变 | 显示选择的数据源、授权是否有效、上次成功查询、源端更新时间（若提供）、是否使用缓存，并给出具体下一步操作 | 低至中 |

建议先做“成绩快照与进步对比”，其次是“目标歌单”。这两项能复用现有双查分器、成绩模型和绘图，对日常玩家的收益最直接；版本差异对照则适合做一个较小的独立改进。

数据可行性核对：

- [水鱼 OAuth 接口文档](https://maimai.diving-fish.com/manual/docs/developer/oauth-api-document/)提供授权后的完整、单曲与按版本成绩，可用于当前成绩快照；当前资料不能凭空还原过去每局成绩。
- [落雪舞萌 API 文档](https://maimai.lxns.net/docs/api/maimai)提供 Recent 50、成绩历史、Rating 趋势、上传热力图及收藏品进度。最近记录依赖增量爬取，历史查询受权限限制，游玩时间可能缺失；这些能力需要单独接入，不能假定当前 Bot 已经获取。
- 谱面技术标签分析暂不排在前面：现有曲库主要有物量、BPM、定数和谱师，不能可靠判断交互、扫键、星星速度等技术点。若以后做弱项诊断，应先维护可核验的技术标签和样本。
- 暂不优先做自动群榜和主动播报：需要另行设计用户参与、群内范围、频率和退出方式；先提供主动查询更容易落地。

维护方面，后续新增命令时应同步核对帮助入口；有条件可从共享命令注册导出命令清单，CI 提醒文档缺项。清单仅检查覆盖，不自动公开受限指令，也不把动态模板别名全部当作独立功能。
